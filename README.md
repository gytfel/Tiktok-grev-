# Очередь публикаций TikTok

Панель для публикации одного видео на много аккаунтов TikTok через официальный
[Content Posting API](https://developers.tiktok.com/doc/content-posting-api-get-started) (сценарий **Direct Post**).

Видео загружается один раз → вы выбираете аккаунты и настройки → система проверяет каждый аккаунт
и показывает экран подтверждения → после подтверждения создаётся отдельное задание на каждый аккаунт,
и панель показывает статус каждого из них.

## Что умеет

- **Реестр аккаунтов.** Подключение через официальный вход TikTok (OAuth), группы, импорт списка из CSV,
  статус авторизации, доступные варианты видимости и лимит длительности для каждого аккаунта.
  Токены хранятся в базе в зашифрованном виде.
- **Медиатека.** Файл загружается один раз и проверяется по требованиям TikTok: формат, кодек,
  разрешение, частота кадров, размер. Считается контрольная сумма sha256.
- **Мастер кампании:** видео → аккаунты → настройки публикации → проверка и запуск.
  - Подпись можно задать общую или свою для отдельного аккаунта.
  - Видимость выбирается вручную, значения по умолчанию нет, как требует TikTok.
  - Комментарии, Duet и Stitch по умолчанию выключены.
  - Есть отметка коммерческого контента, отметка «создано ИИ», выбор кадра обложки и запуск по расписанию.
  - Повторная публикация того же видео на тот же аккаунт блокируется, пока вы её явно не разрешите.
- **Экран подтверждения.** Показывает, какие аккаунты будут опубликованы, какие исключены и почему,
  и согласие с Music Usage Confirmation. Если что-то изменилось между проверкой и подтверждением,
  запуск не произойдёт: панель покажет обновлённый список.
- **Очередь заданий** со статусами, историей попыток и безопасными повторами (подробности ниже).
- **Журнал действий** и роли пользователей панели: администратор, оператор, наблюдатель.
- **Приложение на телефоне** с push-уведомлениями о завершённых кампаниях и проблемных заданиях
  (подробности ниже).
- **Шаблоны:** готовые подписи, наборы хештегов и ответы на комментарии. Вставляются в мастер кампании
  одной кнопкой, работают без AI.
- **AI-помощник:** варианты подписей, хештеги, идеи роликов, варианты ответов на комментарии. Работает с любым
  OpenAI-совместимым сервисом, в том числе бесплатно (подробности ниже).
- **Ответы на комментарии:** черновики ответов зрителям под своими публикациями, история и напоминания.
- **Календарь:** запланированные и прошедшие кампании, напоминания и итоги публикаций по дням. Перенос и
  отмена ещё не начавшихся кампаний, планирование на выбранный день, часовой пояс пользователя.
- **Безопасность:** двухфакторный вход (коды из приложения-аутентификатора), HTTPS через Caddy,
  автоматические резервные копии.

## Чего здесь нет — и не будет

Лайков, комментариев, репостов, «прогрева», имитации действий пользователей и обхода ограничений
или антибот-защиты TikTok здесь нет. Публикация идёт только через официальный API и только от имени
аккаунтов, владельцы которых сами вошли в TikTok и разрешили приложению публикацию.

Панель не отправляет комментарии: она помогает подготовить ответ, а публикует его человек.

## Ограничения TikTok, о которых нужно знать заранее

- **Без аудита приложения** публиковать могут не более **5 аккаунтов за 24 часа**, и только с видимостью
  **«Только я»**. Панель показывает это как ошибку `reached_active_user_cap` или как исключение аккаунта
  на этапе проверки.
- **Аудит** проходят приложения, которые соответствуют
  [Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines).
  TikTok может отказать приложению, сделанному только для внутреннего управления аккаунтами одной команды.
- У каждого автора свой дневной лимит публикаций через API (ошибка `spam_risk_too_many_posts`).
- Redirect URI для входа должен быть **HTTPS-адресом**. Панель должна быть доступна по HTTPS:
  через свой домен или туннель (Cloudflare Tunnel, ngrok и т. п.).

## Быстрый старт с эмулятором TikTok

Эмулятор нужен, чтобы посмотреть всю панель в работе до одобрения приложения в TikTok.
Он повторяет форму запросов и ответов официального API и к настоящему TikTok не подключается.

Нужен Docker с Docker Compose.

```bash
cp .env.example .env
# заполните в .env: SECRET_KEY, TOKEN_ENCRYPTION_KEY, ADMIN_PASSWORD (команды для генерации — в файле)
docker compose -f docker-compose.yml -f docker-compose.emulator.yml up --build
```

Откройте http://localhost:8000 и войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Если в `.env` оставлено
`REQUIRE_2FA=true`, панель сначала попросит включить двухфакторный вход: отсканируйте QR-код приложением-
аутентификатором и введите код. На странице «Аккаунты» нажмите «Подключить аккаунт TikTok» и выберите
любой демо-аккаунт эмулятора.

- `friends_only` разрешает только «Друзья» и «Только я». На нём видно, как аккаунт исключается
  при неподходящей видимости.
- `short_clips` принимает видео не длиннее 15 секунд.
- Чтобы увидеть поведение приложения без аудита, раскомментируйте `EMULATOR_UNAUDITED: "1"`
  в `docker-compose.emulator.yml`.

## Подключение настоящего TikTok

1. На [developers.tiktok.com](https://developers.tiktok.com) создайте приложение и добавьте
   продукты **Login Kit** и **Content Posting API** с включённым **Direct Post**.
   Нужны разрешения `user.info.basic` и `video.publish`.
2. Укажите Redirect URI: `https://<ваш-адрес>/api/oauth/tiktok/callback`.
3. В `.env`:
   ```
   PUBLIC_BASE_URL=https://<ваш-адрес>
   SESSION_HTTPS_ONLY=true
   TIKTOK_CLIENT_KEY=...
   TIKTOK_CLIENT_SECRET=...
   ```
4. Запустите с HTTPS (нужен домен, который указывает на сервер, и открытые порты 80 и 443;
   в `.env` укажите `DOMAIN`):
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
   ```
   Caddy сам получит и будет продлевать сертификат Let's Encrypt. Без своего домена можно запустить
   `docker compose up -d --build` и открыть панель через туннель (Cloudflare Tunnel, ngrok) к `localhost:8000`.
   Порт 8000 по умолчанию доступен только с самого сервера (`APP_BIND=127.0.0.1`).
5. Подключайте аккаунты кнопкой «Подключить». Страница входа TikTok использует ту учётную запись,
   под которой вы вошли в TikTok в этом браузере. Чтобы подключить следующий аккаунт, выйдите из TikTok
   или используйте приватное окно. Если подключаете заранее созданную запись, панель проверит,
   что вход выполнен именно в тот аккаунт, который к ней уже привязан.

## Как работает очередь

| Статус | Что значит |
|---|---|
| В очереди | Ждёт своего времени или свободного воркера |
| Загрузка | Видео загружается в TikTok частями (chunked upload) |
| Обработка в TikTok | Файл передан; результат проверяется через `status/fetch` |
| Опубликовано | TikTok подтвердил публикацию |
| Ошибка | Публикация точно не состоялась; можно повторить |
| Нужна авторизация | Токен отозван или истёк; переподключите аккаунт и повторите |
| Ручная проверка | Результат неизвестен; проверьте профиль и отметьте итог |
| Отменено | Отменено до начала загрузки |

Главное правило: **повтор возможен только тогда, когда точно известно, что публикация не состоялась.**

- Ошибка до передачи файла (токен, проверки, `video/init`) — повтор безопасен. Временные ошибки
  (сеть, `rate_limit_exceeded`, 5xx) повторяются автоматически с растущей паузой. Постоянные
  (`spam_risk_*`, неподходящая видимость) — только вручную.
- Если связь оборвалась во время загрузки, панель не создаёт публикацию заново. Она спрашивает у TikTok
  статус по сохранённому `publish_id`:
  - TikTok получил файл целиком — ждём итога;
  - получил не весь файл — публикация невозможна, и задание безопасно повторяется.
- Если TikTok слишком долго не даёт итог или проверить его нельзя, задание уходит на ручную проверку.
  Вы смотрите профиль и нажимаете «Опубликовано» или «Не опубликовано».
- На одном аккаунте одновременно идёт не больше одной публикации.

Число параллельных загрузок задаёт `UPLOAD_CONCURRENCY` в `.env`.

## Приложение на телефоне и уведомления

Панель устанавливается на телефон как приложение (PWA): с иконкой на экране «Домой», на весь экран
и с push-уведомлениями. На узком экране таблицы показываются карточками, навигация — вкладками внизу.

Телефон должен открывать панель по **HTTPS-адресу** из `PUBLIC_BASE_URL`. Тот же адрес нужен и для входа через TikTok.

**iPhone (iOS 16.4 и новее):**
1. Откройте панель в Safari.
2. Нажмите «Поделиться» → «На экран Домой» → «Добавить».
3. Откройте «Публикации» с экрана «Домой», войдите и перейдите в «Уведомления» → «Включить уведомления».

На iPhone уведомления работают только в приложении, открытом с экрана «Домой», а не во вкладке Safari.

**Android:** откройте панель в Chrome и нажмите «Установить приложение» на странице «Уведомления»
(или меню ⋮ → «Установить приложение»). Затем «Включить уведомления».

**Какие уведомления приходят** (выбираются на каждом устройстве отдельно):
- **«Кампания завершена»** — сколько видео опубликовано и сколько заданий требует внимания.
- **«Задания требуют внимания»** — ошибки, потерянная авторизация, ручная проверка. Приходит одно
  уведомление на кампанию, а не по одному на каждый аккаунт.
- **«Напоминание»** — например, ответить на комментарии к публикации в назначенное время.

Нажатие на уведомление открывает нужную кампанию. Кнопка «Отправить тестовое» на странице «Уведомления»
проверяет доставку на текущее устройство.

Панель принимает подписки только от push-сервисов браузеров: Chrome и Android, Safari и iPhone, Firefox, Edge.
Подписки с других адресов отклоняются, а перенаправления при отправке не выполняются. Так сервер нельзя
заставить отправлять запросы на посторонние адреса.

Ключи для push (VAPID) создаются автоматически при первом использовании и хранятся в базе в
зашифрованном виде. Настраивать ничего не нужно. По желанию можно задать контакт для push-сервисов
в `VAPID_SUBJECT`. Уведомления формирует воркер раз в `NOTIFY_INTERVAL_S` секунд (по умолчанию 20).

## Шаблоны и AI-помощник

**Шаблоны** (раздел «Шаблоны») бывают трёх видов: подписи, наборы хештегов и ответы на комментарии.
Их можно группировать по категориям. В мастере кампании под подписью есть кнопки «Шаблон подписи» и
«Набор хештегов», в ответах на комментарии — «Шаблон ответа». Шаблоны работают всегда, без AI.

**AI-помощник** предлагает варианты подписей, хештеги, идеи роликов и ответы на комментарии.
Он только предлагает: что вставить, решаете вы. Подходит любой сервис с OpenAI-совместимым API,
он задаётся в `.env` (`AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY`). Бесплатные варианты:

- **Локальная модель через Ollama.** Полностью бесплатно, тексты не уходят с сервера:
  ```bash
  docker compose -f docker-compose.yml -f docker-compose.ai.yml up -d --build
  ```
  - При первом запуске скачивается модель `AI_MODEL` (по умолчанию `qwen2.5:3b`, около 2 ГБ).
  - Ей нужно около 4 ГБ свободной памяти. Без видеокарты ответ занимает от нескольких секунд до минуты.
  - Маленькие модели пишут проще облачных, поэтому варианты стоит просматривать.
- **Бесплатные тарифы облачных сервисов**: OpenRouter (модели с пометкой `:free`), Google Gemini, Groq.
  Нужно зарегистрироваться, получить ключ и вписать в `.env` адрес, модель и ключ (примеры — в `.env.example`).
  Лимиты и доступность в разных странах у них меняются.

Если AI не настроен, кнопки AI просто не показываются.

## Календарь

Раздел «Календарь» показывает месяц целиком:
- **кампании по времени старта.** Запланированная отмечена пунктирной рамкой, выполняемая — синим,
  завершённая — зелёным, с проблемами — оранжевым;
- **напоминания** (🔔);
- **итоги дня:** ✓ сколько видео опубликовано, ✕ сколько заданий требует внимания.

Нажмите на день, чтобы открыть панель дня. В ней можно:
- **перенести или отменить кампанию,** которая ещё не началась. Время в прошлом означает «запустить сейчас».
  Каждый перенос записывается в журнал действий;
- **перенести напоминание** или отметить его выполненным;
- **запланировать кампанию на этот день** (мастер откроется с заполненным временем старта)
  или добавить напоминание.

**Часовой пояс** выбирается в правом верхнем углу календаря и сохраняется для пользователя. В нём показываются
все даты панели и вводится время старта, поэтому расписание одинаково на компьютере и на телефоне.
По умолчанию используется пояс устройства. На телефоне календарь компактный: события показаны цветными точками,
подробности — в панели дня. Вкладка «Календарь» есть в нижнем меню.

## Ответы на комментарии и напоминания

Раздел «Комментарии» — черновики ответов зрителям под вашими публикациями. Черновик к конкретной публикации
создаётся кнопкой «Ответ на комментарий» в строке опубликованного задания на странице кампании.
Дальше всё просто:

1. Вставьте комментарий зрителя.
2. Напишите ответ сами, выберите шаблон или попросите варианты у AI.
3. Нажмите «Скопировать и открыть видео», опубликуйте ответ в TikTok.
4. Отметьте черновик как отправленный.

Кнопками «Через час» и «Завтра в 10:00» можно поставить напоминание. В разделе «Напоминания» создаются
и любые другие. В назначенное время приходит push-уведомление.

## Безопасность

- **Двухфакторный вход:** раздел «Безопасность» → «Настроить», подходит любое приложение-аутентификатор.
  С `REQUIRE_2FA=true` (так в `.env.example`) без 2FA пользователь может только настроить её.
  - После 5 неверных кодов проверка блокируется на 15 минут.
  - Один и тот же код нельзя использовать дважды.
  - Если телефон потерян, администратор сбрасывает 2FA в разделе «Пользователи» или командой
    `docker compose exec app python -m app.cli reset-2fa <логин>`.
- **Смена пароля** («Безопасность») завершает все остальные сессии этого пользователя. Пароль — от 10 символов.
- **HTTPS** через Caddy (`docker-compose.https.yml`) или туннель. В `.env` при HTTPS: `SESSION_HTTPS_ONLY=true`.
- **Токены TikTok и ключи push** хранятся в базе в зашифрованном виде (`TOKEN_ENCRYPTION_KEY`).

## Импорт аккаунтов из CSV

```
label;groups;notes
shop-01;Магазин|Россия;основной
shop-02;Магазин;
```

Обязательна только колонка `label`. Несколько групп разделяются символом `|`. Записи с уже существующим
`label` пропускаются. После импорта каждую запись нужно подключить к TikTok.

## Пользователи панели

Первый администратор создаётся из `ADMIN_USERNAME` / `ADMIN_PASSWORD` при первом запуске.
Остальных пользователей можно добавить на странице «Пользователи» или из командной строки:

```bash
docker compose exec app python -m app.cli create-user operator1 --role operator
```

## Резервные копии

Сервис `backup` из `docker-compose.yml` работает сам:
- копию базы делает раз в `BACKUP_INTERVAL_HOURS` часов (по умолчанию 24) в папку `./backups`;
- хранит `BACKUP_KEEP` последних копий;
- новые видео копирует в `./backups/media`.

Сделать копию прямо сейчас:

```bash
docker compose run --rm backup once
```

Восстановление (панель на время останавливается, скрипт спросит подтверждение):

```bash
./scripts/restore.sh backups/db-20261030-020000.dump
```

Важно:
- Папку `backups` периодически копируйте на другой компьютер или в облако. Копия на том же сервере
  не спасёт, если сервер выйдет из строя.
- Отдельно сохраните значение `TOKEN_ENCRYPTION_KEY` из `.env`. Без него сохранённые токены TikTok
  не расшифровать, и все аккаунты придётся подключать заново.

## Разработка

```bash
# backend
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest                                  # SQLite по умолчанию
TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost/test pytest   # на PostgreSQL

# frontend (прокси /api → localhost:8000)
cd frontend && npm install && npm run dev
```

Структура:

```
backend/
  app/
    tiktok/            клиент Login Kit и Content Posting API
    publishing.py      кампании, проверка аккаунтов, очередь, правила повторов
    accounts_service.py  OAuth, токены, creator_info
    worker.py          Celery: загрузки, диспетчер, опрос статусов, уведомления
    push.py            Web Push (VAPID)
    notifications.py   какие уведомления отправить
    ai.py              AI-помощник (OpenAI-совместимый API)
    twofactor.py       двухфакторный вход (TOTP)
    routers/           REST API панели
  alembic/             миграции базы
  fake_tiktok/         эмулятор TikTok API для разработки и тестов
  tests/
frontend/              React + TypeScript, PWA (public/manifest.webmanifest, public/sw.js)
infrastructure/        Caddyfile для HTTPS
scripts/               резервное копирование и восстановление
docker-compose*.yml    основной стек; .emulator — эмулятор TikTok; .https — Caddy; .ai — Ollama
```
